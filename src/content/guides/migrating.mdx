One command imports an existing documentation site into a new Thally project. Pick the guide for the platform you use today, or start with the generic version below.

## Migrate and run locally

```bash
npx --yes @thallylabs/cli@latest migrate https://github.com/example/product
```

```bash
cd product-docs
npm run dev
```

Open [http://localhost:3040](http://localhost:3040). Your docs are running on Thally.

The command clones the repository, detects the platform, converts the pages, installs dependencies, runs the checks and a production build, and makes an initial Git commit. Add an output directory after the URL to change the default `<repo>-docs` name.

Mintlify and Docusaurus have dedicated adapters that keep the source navigation and configuration. On another platform, run the generic command above: Thally auto-detects the source, imports every Markdown and MDX page, and generates navigation from the folder structure.

## Options

| Flag | Description |
|------|-------------|
| `--platform <name>` | `mintlify`, `docusaurus`, or `auto`. Without it, the CLI asks. |
| `--yes`, `-y` | Skip all prompts |
| `--branch <name>` | Override the detected branch |
| `--docs-dir <path>` | Override the detected docs folder. A `tree/<branch>/<dir>` URL sets both. |
| `--max-pages <count>` | Cap a live-site crawl at 1 to 1,000 pages |
| `--into <dir>` | Merge into an existing Thally project instead of creating one |
| `--api-key <key>` | Anthropic API key for converting non-Markdown files such as `.rst` |
| `--skip-validation` | Import only; skip install, checks, and build |

Thally detects the platform of a repository from these files, in order: `mint.json` or a Mintlify `docs.json` (Mintlify), `docusaurus.config.*` (Docusaurus), `SUMMARY.md` (GitBook), `.vitepress/` (VitePress), `astro.config.*` (Starlight), `_meta.json` (Nextra). Anything else is treated as plain Markdown. The docs folder is the first of `docs/`, `documentation/`, `content/`, `pages/`, `src/content/`, `src/pages/`, `guide/`, or `guides/` that contains Markdown, falling back to the repository root.

## Publish

Commit your edits, push the project to a new GitHub repository, and connect it in [Thally Cloud](https://app.thally.io) with **Create site** and then **Connect an existing repository**:

```bash
git add -A
git commit -m "docs: review migrated content"
git branch -M main
gh repo create product-docs --private --source=. --remote=origin --push
```

Set `repoUrl` in `src/data/site.ts` to the new repository so edit links work. To host it yourself, see [Deploy your documentation site](/guides/deploying).

## Troubleshooting

- **Pages are missing.** For a repository, pass `--docs-dir` or a `tree/<branch>/<dir>` URL. For a live site, raise `--max-pages` and rerun into an empty directory.
- **The build failed.** Open `migration-report.json` and the build output. The usual causes are imports of packages Thally does not ship, template syntax MDX cannot parse, and components with no Thally equivalent. Fix the page, then run `npx --yes @thallylabs/cli@latest check` and `npm run build`.
- **Thally Cloud cannot see the repository.** Grant the Thally GitHub App access to it from the source step, then reload the repository list.
- **The repository is rejected as incompatible.** Commit every generated file, including `package-lock.json`, `wrangler.jsonc`, and `open-next.config.ts`.
