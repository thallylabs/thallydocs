Utilisez `<RequestExample>` et `<ResponseExample>` pour présenter vos exemples HTTP
dans des cartes distinctes et étiquetées. Placez chaque bloc de code directement
dans son composant. Les variantes de requête apparaissent dans un menu de
langages et les variantes de réponse dans des onglets de statut.

## Langages de requête et statuts de réponse

<RequestExample>
```bash cURL
curl -X POST https://api.example.com/pets \
  -H "Content-Type: application/json" \
  -d '{"name": "Buddy", "species": "dog"}'
```

```python Python
import requests

response = requests.post(
    "https://api.example.com/pets",
    json={"name": "Buddy", "species": "dog"},
)
```
</RequestExample>

<ResponseExample>
```json 201 Created
{ "id": "pet_123", "name": "Buddy", "species": "dog" }
```

```json 400 Bad Request
{ "error": "A pet name is required." }
```
</ResponseExample>

Indiquez le langage de chaque bloc de requête, par exemple `cURL` ou `Python`.
Le langage sélectionné est partagé avec les groupes de code compatibles, les
cartes de requête API générées et la fenêtre Try it. Si un groupe ne propose pas
ce langage, il conserve un choix précédent compatible ou affiche son premier
exemple. Cette préférence est conservée après un rechargement lorsque le
stockage du navigateur est disponible.

Indiquez le code de statut et, si nécessaire, une description pour chaque bloc
de réponse, par exemple `201 Created` ou `400 Bad Request`. Vous pouvez
sélectionner un onglet de statut ou passer d'un onglet à l'autre avec les touches
fléchées. Le changement de statut ne modifie pas le langage de requête. Sur les
petits écrans, les onglets gardent le code de statut visible et masquent la
description plus longue.

Ces réponses sont des exemples rédigés dans votre documentation. Pour afficher
une réponse réelle de l'API, utilisez [Try it](/fr/guides/api-playground).

## Relier les champs aux exemples

Sur la page d'un endpoint API, survoler ou sélectionner au clavier une ligne de
paramètre ou une ligne de code liée met en évidence les noms de champs
correspondants dans la documentation et les exemples. Utilisez les mêmes noms
dans vos composants `ParamField` et `ResponseField` et dans les clés des exemples.
Les liens sont déduits des emplacements reconnus de noms de champs, comme les
clés JSON, plutôt que de toute occurrence du même texte.
