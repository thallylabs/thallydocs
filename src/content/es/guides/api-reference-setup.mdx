## Añade tu especificación

Coloca tu archivo de especificación OpenAPI 3.x en la raíz del proyecto como `openapi.yaml` (o `openapi.json`). Luego configúralo en `docs.json`.

```json
{
  "tab": "API Reference",
  "api": {
    "source": "openapi.yaml",
    "tagsOrder": ["Users", "Orders", "Products"],
    "defaultGroup": "General"
  }
}
```

La pestaña de referencia de API generará automáticamente una página para cada operación de tu especificación.

## Navega por un endpoint

Cada endpoint muestra su método HTTP, como `GET` o `POST`, antes de su nombre en la barra lateral y el menú móvil. Thally lee el método de los metadatos de la operación, así que no necesitas añadirlo al título. Las páginas creadas por ti vinculadas con frontmatter `openapi` o descritas con frontmatter `api` también reciben etiquetas de método.

En pantallas amplias, la documentación de parámetros aparece junto a tarjetas separadas de solicitud y respuesta. En pantallas más estrechas, las tarjetas pasan encima de los parámetros. La barra del endpoint permite copiar la URL o abrir **Try it**.

Elige un lenguaje de solicitud en la cabecera de la tarjeta; los grupos de código compatibles y la ventana Try it comparten esa elección. Las pestañas de respuesta cambian entre los estados documentados en tu especificación. Pasa el cursor o enfoca un parámetro o una línea de código vinculada para resaltar los nombres de campo correspondientes en la documentación y los ejemplos.

## Opciones de configuración

| Campo | Obligatorio | Descripción |
| --- | --- | --- |
| `source` | Sí | Ruta a tu archivo de especificación OpenAPI, relativa a la raíz del proyecto. |
| `navigation` | No | Define `false` cuando las páginas MDX creadas por ti proporcionan la navegación de API. Valor predeterminado: `true`. |
| `tagsOrder` | No | Controla el orden en que aparecen las etiquetas en la barra lateral. Las etiquetas no listadas aparecen después. |
| `defaultGroup` | No | Nombre del grupo para operaciones sin etiquetas. Valor predeterminado: `"Endpoints"`. |
| `webhookGroup` | No | Nombre del grupo para operaciones de webhook de OpenAPI. Valor predeterminado: `"Webhooks"`. |
| `overrides` | No | Personalizaciones por operación (ver más abajo). |

## Sobrescritura de operaciones

Puedes personalizar cómo aparecen las operaciones individuales en la barra lateral y la documentación.

```json
{
  "api": {
    "source": "openapi.yaml",
    "overrides": {
      "GET /users": {
        "title": "List users",
        "description": "Fetch all users with pagination.",
        "badge": "Stable"
      },
      "DELETE /users/{id}": {
        "title": "Delete user",
        "badge": "Destructive"
      }
    }
  }
}
```

El formato de la clave es `METHOD /path`, que coincide con el `method` y el `path` de tu especificación OpenAPI.

Campos de sobrescritura disponibles.

- **`title`** — título personalizado de la barra lateral y la página
- **`description`** — descripción personalizada que se muestra debajo del título
- **`badge`** — una etiqueta que se muestra junto al título de la operación
- **`group`** — mover la operación a un grupo diferente en la barra lateral
- **`slug`** — reemplaza los segmentos de URL generados por un array de cadenas
- **`hidden`** — mantiene la operación fuera de la navegación generada

## Orden de etiquetas

De forma predeterminada, las operaciones se agrupan por sus `tags` de OpenAPI. El array `tagsOrder` controla el orden en la barra lateral.

```json
"tagsOrder": ["Authentication", "Users", "Orders"]
```

Las etiquetas no listadas en `tagsOrder` aparecen después de las listadas, en el orden en que aparecen por primera vez en la especificación.

## Ventana Try it

Cada página de operación de API incluye un botón **Try it** que abre una ventana modal interactiva. La ventana hace lo siguiente.

- Rellena previamente los parámetros desde el esquema OpenAPI
- Marca valores obligatorios ausentes y tipos de campo inválidos antes de enviar, y enfoca el primer campo inválido
- Envía solicitudes a través de un proxy del lado del servidor para evitar problemas de CORS
- Muestra la respuesta con el código de estado, las cabeceras y el cuerpo
- Genera un comando cURL que puedes copiar

En teléfonos, la ventana ocupa toda la pantalla y mantiene **Send** accesible en la parte inferior. Pulsa Escape o usa el botón de cierre para volver al endpoint.

Try it está listo cuando la especificación proporciona al menos una URL de servidor. Añade marcadores de posición de autenticación solo cuando tu API los requiera; los lectores pueden introducir sus propias credenciales antes de enviar una solicitud.

## Varias especificaciones de API

Un sitio que documenta más de una API puede vincular una especificación OpenAPI diferente a cada pestaña. La primera pestaña con API mantiene las rutas predeterminadas en `/api/default/...`; cada pestaña adicional enruta sus operaciones bajo `/api/<tabId>/...`, donde `tabId` es la versión slug de la etiqueta de la pestaña.

```json
{
  "tabs": [
    {
      "tab": "REST API",
      "api": {
        "source": "openapi.yaml",
        "tagsOrder": ["Users", "Orders"]
      }
    },
    {
      "tab": "Admin API",
      "api": {
        "source": "admin-openapi.yaml",
        "defaultGroup": "Admin"
      }
    }
  ]
}
```

En este ejemplo, las operaciones REST aparecen bajo `/api/default/...` y las operaciones Admin bajo `/api/admin-api/...`. Cada pestaña genera su propia navegación en la barra lateral y cada especificación se analiza de forma independiente, así que las etiquetas, sobrescrituras y grupos se limitan a la pestaña que los posee.

## Reemplaza la especificación de ejemplo

La plantilla incluye una especificación de JSONPlaceholder para que puedas probar las páginas generadas sin credenciales. Para usar tu propia API, sigue estos pasos.

1. Reemplaza `openapi.yaml` con tu especificación
2. Actualiza el `tagsOrder` de `docs.json` para que coincida con tus etiquetas
3. Añade las `overrides` que quieras
4. Ejecuta `npm run dev` para ver el resultado

## Verifica la referencia generada

Confirma que aparecen las etiquetas y operaciones esperadas, abre al menos un endpoint y compara sus parámetros y esquemas con la especificación de origen. Luego ejecuta estos comandos.

```bash
npx --yes @thallylabs/cli@latest check
npm run build
```
