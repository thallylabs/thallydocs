## Agregar tu especificación

Coloca tu archivo de especificación OpenAPI 3.x en la raíz del proyecto como `openapi.yaml` (o `openapi.json`). Luego configúralo en `docs.json`:

```json
{
  "tab": "API Reference",
  "api": {
    "source": "openapi.yaml",
    "tagsOrder": ["Users", "Orders", "Products"],
    "defaultGroup": "General"
  }
}
```

La pestaña de Referencia de API generará automáticamente una página para cada operación en tu especificación.

## Navegar por un endpoint

Cada endpoint muestra su método HTTP, como `GET` o `POST`, antes del nombre en
la barra lateral y el menú móvil. Thally lo obtiene de los metadatos de la
operación; no hace falta añadirlo al título. Las páginas MDX vinculadas con
frontmatter `openapi` o descritas con frontmatter `api` también muestran el método.

En pantallas amplias, los parámetros aparecen junto a tarjetas separadas de
solicitud y respuesta. En pantallas más estrechas, las tarjetas pasan encima de
los parámetros. La barra del endpoint permite copiar la URL o abrir **Try it**.

El lenguaje elegido en la tarjeta se comparte con los grupos compatibles y la
ventana Try it. Las pestañas de respuesta muestran los estados documentados en
la especificación. Al pasar el cursor o enfocar un parámetro o una línea vinculada,
se resaltan los nombres de campo correspondientes en la documentación y los ejemplos.

## Opciones de configuración

| Campo | Requerido | Descripción |
| --- | --- | --- |
| `source` | Sí | Ruta a tu archivo de especificación OpenAPI, relativa a la raíz del proyecto. |
| `tagsOrder` | No | Controla el orden en que aparecen las etiquetas en la barra lateral. Las etiquetas no listadas aparecen después. |
| `defaultGroup` | No | Nombre del grupo para operaciones sin etiquetas. Por defecto es `"Endpoints"`. |
| `overrides` | No | Personalizaciones por operación (ver más abajo). |

## Sobreescritura de operaciones

Puedes personalizar cómo aparecen las operaciones individuales en la barra lateral y la documentación:

```json
{
  "api": {
    "source": "openapi.yaml",
    "overrides": {
      "GET /users": {
        "title": "List users",
        "description": "Fetch all users with pagination.",
        "badge": "Stable"
      },
      "DELETE /users/{id}": {
        "title": "Delete user",
        "badge": "Destructive"
      }
    }
  }
}
```

El formato de la clave es `METHOD /path` — que coincide con el `method` y el `path` de tu especificación OpenAPI.

Campos de sobreescritura disponibles:

- **`title`** — título personalizado de la barra lateral y la página
- **`description`** — descripción personalizada que se muestra debajo del título
- **`badge`** — una etiqueta que se muestra junto al título de la operación
- **`group`** — mover la operación a un grupo diferente en la barra lateral
- **`slug`**: reemplazar los segmentos de URL generados con un array de cadenas
- **`hidden`**: mantener la operación fuera de la navegación generada y de los archivos `/openapi.json` y `/openapi.yaml` publicados

Una página cuyo frontmatter `openapi:` nombra una operación oculta aún la renderiza: `x-hidden` y la opción `hidden` solo mantienen una operación fuera de la navegación generada y las páginas generadas. La página no tiene botón Try it para esa operación, porque el playground solo reenvía solicitudes a operaciones listadas.

Una página cuyo frontmatter `openapi:` nombra una operación excluida (`x-excluded: true`) no se publica. Su dirección devuelve 404 y se omite de la navegación, la búsqueda, el sitemap, `llms.txt`, las páginas Markdown y los listados de agentes y MCP. `thally check` y la compilación advierten sobre cada una de estas páginas.

## Enlazar a un campo

Cada parámetro, campo del cuerpo de la solicitud y campo de respuesta en una página de API tiene un id al que se puede enlazar: `#parameter-<name>`, `#body-<path>` y `#response-<path>`. Cada nombre está en kebab case y unido por `-`, así que `explicitDeposit` se convierte en `#body-explicit-deposit`. Los campos de elementos de un array van bajo `items` (`#response-requests-items-data`). Un campo que puede ser null o que es uno de varios tipos agrega `-one-of-` y el índice basado en cero del tipo, omitiendo null (`#body-invoice-id-one-of-0`). Un nombre que se usa dos veces en una página se numera desde `-2`. `thally check` acepta estos ids en una página que documenta una operación.

## Ordenamiento de etiquetas

Por defecto, las operaciones se agrupan por sus `tags` de OpenAPI. El array `tagsOrder` controla el orden en la barra lateral:

```json
"tagsOrder": ["Authentication", "Users", "Orders"]
```

Las etiquetas no listadas en `tagsOrder` aparecen después de las listadas, en el orden en que aparecen por primera vez en la especificación.

## Ventana Try it

Cada página de operación de API incluye un botón **Try it** que abre una ventana modal interactiva. Esta:

- Rellena previamente los parámetros desde el esquema OpenAPI
- Marca valores obligatorios ausentes y tipos inválidos antes de enviar, y enfoca el primer campo con error
- Envía solicitudes a través de un proxy del lado del servidor para evitar problemas de CORS
- Muestra la respuesta con el código de estado, encabezados y cuerpo
- Genera un comando cURL que puedes copiar

En teléfonos, la ventana ocupa toda la pantalla y mantiene **Send** accesible en
la parte inferior. Pulsa Escape o el botón de cierre para volver al endpoint.

La especificación debe incluir al menos una URL de servidor. Las solicitudes se
envían al servidor seleccionado y pueden modificar sus datos. Usa credenciales
adecuadas para ese servidor; la ventana no crea un entorno de pruebas simulado.

## Varias especificaciones de API

Un sitio que documenta más de una API puede vincular una especificación OpenAPI
diferente a cada pestaña. La primera pestaña con API mantiene las rutas
predeterminadas en `/api/default/...`; cada pestaña adicional enruta sus operaciones
bajo `/api/<tabId>/...`, donde `tabId` es la versión slug de la etiqueta de la
pestaña.

```json
{
  "tabs": [
    {
      "tab": "REST API",
      "api": {
        "source": "openapi.yaml",
        "tagsOrder": ["Users", "Orders"]
      }
    },
    {
      "tab": "Admin API",
      "api": {
        "source": "admin-openapi.yaml",
        "defaultGroup": "Admin"
      }
    }
  ]
}
```

En este ejemplo, las operaciones REST aparecen bajo `/api/default/...` y las operaciones
Admin bajo `/api/admin-api/...`. Cada pestaña genera su propia
navegación en la barra lateral y cada especificación se analiza de forma
independiente, por lo que las etiquetas, sobreescrituras y grupos se limitan a la
pestaña que los posee.

## Reemplazar la especificación de ejemplo

La plantilla incluye un ejemplo de JSONPlaceholder. Para usar tu propia API:

1. Reemplaza `openapi.yaml` con tu especificación
2. Actualiza el `tagsOrder` en `docs.json` para que coincida con tus etiquetas
3. Agrega los `overrides` que desees
4. Ejecuta `npm run dev` para ver el resultado
