Comienza cada página con un objetivo de lectura. Separar el contenido de aprendizaje, tareas, explicaciones y búsqueda hace que un conjunto de documentación sea más fácil de escanear y mantener.

## Tutorial

Usa un tutorial para ayudar a un lector nuevo a alcanzar un resultado completo en su primer intento. Proporciona los requisitos previos, una secuencia guiada, un paso claro de verificación y tareas enfocadas siguientes.

El [Quickstart](/quickstart) es un tutorial: crea un sitio, agrega una página y verifica el resultado en una sola ruta.

## Guía práctica

Usa una guía práctica para un trabajo específico que el lector ya entiende, como implementar en Cloudflare o proteger un sitio con una contraseña.

Una página de tareas útil generalmente sigue este orden:

1. Establece el resultado.
2. Lista los requisitos previos.
3. Da el procedimiento más corto y confiable.
4. Muestra cómo verificarlo.
5. Cubre probables fallos cerca de la tarea.
6. Vincula a los próximos trabajos relacionados.

Nombra páginas de tareas con verbos: **Implementar en Vercel**, **Agregar fragmentos reutilizables**, o **Configurar el área de pruebas de API**.

## Concepto

Usa una página de concepto para explicar cómo se comporta un sistema o por qué una decisión es importante. Las páginas de concepto deben aclarar un modelo mental, no ocultar un procedimiento de configuración largo.

Los ejemplos incluyen [Cómo funciona Thally](/architecture) y el [flujo de cambio de producto](/product-change-pipeline).

## Referencia

Usa una página de referencia para hechos completos y escaneables: campos de configuración, comandos, componentes, variables de entorno o puntos finales de API. Prefiere tablas, firmas, valores predeterminados y restricciones sobre narrativa.

Las páginas de referencia no deben ser el único lugar donde un principiante pueda descubrir una tarea. Vincula a ellas desde la guía relevante, luego vincula de nuevo a un ejemplo práctico.

## Entrada del registro de cambios

Usa el registro de cambios para un cambio de producto con fecha. Explica qué cambió, a quién afecta y qué necesita hacer el lector. No lo uses como sustituto de actualizar la guía permanente o página de referencia.

## Lista de verificación de página

- ¿El título coincide con una intención de lectura?
- ¿Está claro el resultado esperado en el primer párrafo?
- ¿Están los requisitos previos antes de las instrucciones?
- ¿Puede el lector verificar el éxito?
- ¿Son los ejemplos reales y copiables?
- ¿La página vincula a la siguiente tarea en lugar de repetirla?
